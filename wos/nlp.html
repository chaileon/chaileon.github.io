World of Science 2026

Natural Language Processing

From Chomsky to ChatGPT and Beyond

Hai Leong Chieu  ·  May 2026

NLP is the subfield of AI concerned with enabling computers to understand, generate, and reason about human language. It sits at the intersection of linguistics, computer science, and statistics. Today we'll trace its history from formal grammar theory through the current revolution of large language models.

What Is NLP?

  • Getting computers to understand and generate human language
  • Human language is ambiguous, context-dependent, and constantly evolving
  • Classic tasks: translation, summarisation, question answering, sentiment analysis
  • Modern framing: a single large model that does all of these at once
Language is ambiguos in many ways, making it hard for computers before large language models, e.g., ambiguity in word sense
"The bank by the river was steep." vs "The bank refused my loan."
The word-sense disambiguation example is a classic NLP motivating problem. Humans resolve this instantly from context; early NLP systems needed hand-crafted disambiguation rules for every ambiguous word.

Section 1

Classical NLP

Rules, grammars, and the linguistics era

1957 Chomsky & Formal Language Theory

  • Noam Chomsky publishes Syntactic Structures — language has underlying structure
  • Proposes the Chomsky Hierarchy: a classification of formal grammars by expressive power
  • Regular → Context-Free → Context-Sensitive → Unrestricted
  • Argues that human language acquisition cannot be explained by behaviorism alone — there must be an innate Universal Grammar
Huge influence on early NLP: if language has formal structure, maybe we can write programs to parse it systematically.
Chomsky's debate with behaviorist B.F. Skinner is one of the most famous in 20th-century science. Chomsky argued children couldn't learn language from data alone — they must have innate linguistic knowledge. Ironically, modern LLMs suggest you CAN learn a lot from data alone, which has re-opened this debate.

Regular Expressions: The Simplest NLP Tool

  • Lowest level of the Chomsky Hierarchy — regular languages
  • A pattern language for matching character sequences
  • Still the first tool every NLP engineer reaches for: tokenisation, preprocessing, rule-based extraction
  • Recognised by a finite automaton — no memory beyond current state
Key limitation: regex cannot count.
Matching balanced brackets ((())) requires knowing the nesting depth — that needs a stack, which regular languages don't have.
→ This is exactly what CFGs solve.

NLP examples in Python regex:

# Tokenise words
\b\w+\b

# Possible proper noun (NER bootstrap)
\b[A-Z][a-z]+\b

# Date patterns
\d{1,2}[\/\-]\d{1,2}[\/\-]\d{2,4}

# Negation words
\b(not?|never|hardly)\b

# Email address
[\w.+\-]+@[\w\-]+\.\w+

# Fails: can't validate nested quotes
# "She said 'he said "hello"'"
Regular expressions were formalised by Stephen Kleene in 1951, before Chomsky's hierarchy. In NLP, regex is still used heavily in production systems for fast rule-based matching — spaCy's EntityRuler, for example, lets you define regex patterns for custom NER. The finite automaton equivalence means regex can be compiled into extremely fast state machines. The inability to match a^n b^n (n "a"s followed by n "b"s) is the classic proof that regular languages are insufficient for natural language syntax — nested sentences, relative clauses, and recursive noun phrases all require at least context-free power.

Context-Free Grammars (CFGs)

  • A set of rewrite rules describing valid sentence structures
  • S → NP VP    (sentence = noun phrase + verb phrase)
  • NP → Det N    ("the cat")
  • VP → V NP    ("chased the mouse")
  • Parsers use CFGs to build parse trees — hierarchical structure of sentences
Used heavily in compilers too — programming languages are defined by CFGs.
CFG parsers were the backbone of NLP systems from the 1960s through the 1990s. The problem: real natural language constantly violates CFG assumptions — sentences can be ambiguous in exponentially many ways, and handling all edge cases requires enormous hand-crafted rule sets.

Part-of-Speech Tagging & the Penn Treebank

  • Assign a grammatical label to every word: noun, verb, adjective…
  • 1993 Penn Treebank (Univ. of Pennsylvania): 1M+ words of Wall Street Journal text, manually annotated
  • Defines 45 POS tags — the standard tagset used for decades
  • Enabled the shift from hand-written rules to statistical taggers (HMMs, then CRFs)
  • Funded by DARPA over ~8 years; annotators parsed only 300–400 words per hour — today a pre-trained model tags a million words in seconds
Same word, three tags:  light as NN / JJ / VB

Example (Penn Treebank tags):

TheDT  catNN  quicklyRB  satVBD  onIN  theDT  matNN

Selected tags from the 45-tag set:

The Penn Treebank project ran from 1989–1996 at UPenn, led by Mitchell Marcus, funded by DARPA and AFOSR. It contains ~4.5 million words across WSJ, Brown corpus, and other sources. Annotators worked at 300–400 words per hour — the scale of manual effort across 8 years implies tens of thousands of person-hours, though no total cost figure was publicly disclosed. The 45-tag POS tagset includes separate tags for different verb forms (VB, VBD, VBG, VBN, VBP, VBZ). The full tagset also includes punctuation tags.

Full Parse: CFG → POS Tags → Words

Grammar rules used:

S  → NP VP
NP → DT NN
VP → VBD PP
PP → IN NP
DT → "the" | "The"
NN → "cat" | "mat"
VBD → "sat"
IN  → "on"
The lexicon (yellow rules) maps POS tags to actual words. Parsing works top-down from S, or bottom-up from words.
The dashed yellow lines represent lexical rules — the bottom of the grammar where syntactic categories link to actual vocabulary items. In a real grammar there would be thousands of these lexical rules, one per word-tag pair. The parse can be read top-down (prediction) or bottom-up (recognition). Ambiguous sentences can have multiple valid parse trees — "I saw the man with the telescope" has two: did I use the telescope, or did the man have it? This "PP attachment ambiguity" is one of the central challenges of parsing.

Dependency Parsing

  • Represent sentences as binary head–dependent relations, each labelled
  • Each word has exactly one head; arcs can point left or right
  • Universal Dependencies (UD): same label set across 100+ languages
Relative clauses: a striking contrast
English: noun then relative clause
"The book I bought was expensive"

Chinese: relative clause then noun
「我买的 书 很贵」(I-bought-DE book very-expensive)
The arc for acl (adjectival clause) points → right in English and ← left in Chinese — same label, opposite direction.

English — relative clause after noun

Chinese — relative clause before noun (我买的书很贵)

↑ acl arc points → right in English, ← left in Chinese — same label, mirrored structure

The relative clause example beautifully captures a deep typological difference. English is head-initial for relative clauses: the head noun comes first, the modifying clause follows. Chinese (and Japanese, Korean, Turkish…) are head-final: modifiers precede the head noun. The particle 的 (de) marks the right boundary of the Chinese relative clause — it has no English equivalent. In UD both languages use "acl" (adjectival clause) as the relation label, but the arc points right in English (dependent after head) and left in Chinese (dependent before head). Modern neural parsers (Biaffine parser, Dozat & Manning 2017) handle both directions natively, achieving >95% UAS on standard benchmarks in under 50ms per sentence.

Named Entity Recognition (NER)

  • Identify and classify real-world entities in text: people, places, organisations, dates, amounts…
[Barack Obama]PER visited [Singapore]LOC in [November 2012]DATE to meet leaders from [ASEAN]ORG.
  • Applications: information extraction, search, financial analysis, clinical NLP
  • Classical: hand-crafted gazetteers + rules → statistical sequence models (CRFs) → transformers
  • Key challenge: ambiguity — "Apple" could be a company, a fruit, or a person's name
NER was one of the main shared tasks at MUC (Message Understanding Conferences) in the 1990s, which drove a lot of early NLP progress. CRFs (Conditional Random Fields) dominated from ~2003–2018. Today, BERT-based models achieve F1 > 93% on standard benchmarks.

Coreference Resolution

  • Determine which words or phrases refer to the same entity in a text
The scientist ran the experiment. She found that the result confirmed it was valid.
  • Critical for: reading comprehension, summarisation, dialogue systems
  • Winograd Schema challenge: pronoun resolution requiring world knowledge
"The trophy didn't fit in the suitcase because it was too big." — what is "it"?
Humans know instantly. Classical NLP systems almost always got it wrong.
The Winograd Schema Challenge was proposed as an alternative to the Turing Test — pronoun resolution that requires genuine world knowledge. "The trophy didn't fit in the suitcase because it was too big" — the answer (trophy) requires reasoning about physical size relationships. GPT models now solve most Winograd schemas correctly.

Statistical NLP: Rules → Data

  • 1990s The field shifts from hand-crafted rules to learning from data
  • Key idea: count how often patterns appear in large text corpora — use probabilities
  • n-gram language models: predict next word from the previous n words
  • Hidden Markov Models: sequence labelling (POS, NER)
  • Support Vector Machines: text classification
The IBM machine translation papers (1990–93) showed that a model trained purely on statistics, with no linguistic knowledge, could outperform hand-crafted rule systems. A turning point.
Fred Jelinek's famous quote: "Every time I fire a linguist, the performance of the speech recognizer goes up." Brutal — but it captured the empirical finding that data-driven statistical models consistently beat hand-engineered linguistic systems when given enough data.

1990–93 IBM Statistical Translation Models

  • Fred Jelinek's team at IBM Watson Research Center
  • Key insight: treat translation as a noisy channel problem
  • Trained on the Canadian Hansards — 2.2 million French/English sentence pairs from Parliament
  • No bilingual dictionary, no grammar rules — only parallel text
  • EM algorithm discovers word alignments automatically from data
  • IBM Models 1–5: progressively richer alignment assumptions
The noisy channel:
P(English | French) ∝ P(French | English) × P(English)
translation model  ×  language model
IBM Model 1 — learn P(foreign word | English word) for all pairs. Every alignment equally likely.

IBM Model 2 — add absolute position bias: word at position i tends to align near position j.

IBM Model 3 — add fertility: one source word can generate multiple target words
e.g. French "ne … pas" ← English "not"
"Every time I fire a linguist, the performance of the speech recogniser goes up."
— Fred Jelinek, IBM
Brown, Della Pietra, Della Pietra, and Mercer (1993) "The Mathematics of Statistical Machine Translation" in Computational Linguistics. The Canadian Hansards were ideal training data: every speech is recorded in both official languages, giving perfectly aligned sentence pairs. The EM algorithm iterates: (E-step) assign soft alignments given current parameters; (M-step) re-estimate parameters from those soft counts. After many iterations, the model converges on meaningful word-to-word translation probabilities.

Word Alignment: The Hidden Variable

  • Alignment = a mapping from each target word to a source word
  • Never observed in training — a latent variable inferred by EM
  • Languages differ in word order — alignments frequently cross
English adjective precedes noun: "black cat"
French adjective follows noun: "chat noir"
The alignment lines for these two words cross — the model must learn this from data alone.
IBM models → phrase-based MT (Koehn et al. 2003) → neural MT (2014) → Transformer (2017).
The statistical era laid the foundations for everything that followed.
The crossing alignment (called a "non-monotonic" alignment) is common between English and French for adjective-noun pairs, and extremely common for English-Japanese or English-Chinese where word order differences are far more radical. IBM Model 1 allows any alignment; Models 2–5 progressively penalise or model long-distance reorderings. The fertility concept in Model 3 handles morphologically rich languages where one English word maps to several target tokens.

Section 2

The Neural Turn

Word embeddings, sequence models, and the Transformer

2013 Word Embeddings: Meaning as a Vector

  • Word2Vec (Google, 2013): map every word to a dense vector in high-dimensional space
  • Words with similar meanings end up close together in that space
  • Arithmetic works on meaning:
king − man + woman ≈ queen
  • The network never "reads" a definition — it learns meaning from context patterns alone
  • GloVe (Stanford, 2014), FastText (Facebook, 2016) followed with improvements
  • Problem: one fixed vector per word — "bank" gets one representation regardless of context
Word2Vec was a watershed moment. The king-queen analogy showed that neural networks were encoding genuine semantic relationships. The limitation — one vector per word — was solved by ELMo (2018) and then BERT (2018), which produce context-dependent representations.

2017 The Transformer Changes Everything

  • "Attention Is All You Need" (Vaswani et al., Google, 2017)
  • Replaces recurrent networks — processes all words in parallel
  • Self-attention: every word attends to every other word simultaneously
  • Enables training on far larger datasets — no sequential bottleneck
  • Originally for machine translation — quickly taken over every NLP task
Before Transformers, translating a 100-word sentence required 100 sequential steps. Transformers process all 100 words at once.
Encoder: reads and understands text (BERT family)
Decoder: generates text (GPT family)
Both: translation (original Transformer, T5)
The parallelism is the key practical advantage — it means you can use GPUs/TPUs maximally efficiently. RNNs were fundamentally sequential. The attention mechanism also handles long-range dependencies much better than LSTMs.

2018 Two Paradigms: BERT vs GPT

BERT (Google)

  • Bidirectional encoder
  • Trained by predicting masked words: "The [MASK] sat on the mat"
  • Great at understanding — classification, NER, question answering
  • Cannot generate new text

GPT (OpenAI)

  • Left-to-right decoder
  • Trained by predicting the next word
  • Great at generating text
  • Scales to become a general-purpose system
In 2018–2020, BERT dominated NLP benchmarks. By 2022–25, the GPT paradigm won — generation at scale turned out to be the more powerful approach.
BERT achieved state-of-the-art on 11 NLP tasks simultaneously when released — a stunning result. But the autoregressive (GPT-style) approach turned out to scale better and be more flexible. The debate is essentially resolved now: most frontier models are decoder-only.

Section 3

Modern Architectures

Scaling laws and Mixture of Experts

Scaling Laws

  • Kaplan et al. (OpenAI, 2020): model performance follows predictable power laws with scale
  • More parameters + more data + more compute → reliably better models
  • Chinchilla (DeepMind, 2022): earlier models were undertrained — optimal ratio is roughly 20 tokens per parameter
  • This shifted the field: train smaller models on much more data
LLaMA 3 (8B parameters) trained on 15 trillion tokens outperforms GPT-3 (175B parameters) trained on 300B tokens. Size isn't everything — training data volume matters enormously.
The Chinchilla result was a wake-up call: GPT-3 and its contemporaries were massively under-trained relative to their size. The compute-optimal strategy requires matching data volume to model size. This led to the "efficient but data-heavy" approach seen in LLaMA 3, Qwen 2.5, and DeepSeek V3.

Mixture of Experts (MoE): The Idea

  • Instead of one large dense neural network, use many specialised sub-networks ("experts")
  • A learned router selects which 2–4 experts to activate for each input token
  • Only the selected experts do work — most of the model sits idle for any given token
Analogy: A hospital with 20 specialist doctors. Each patient sees only 2–3 relevant specialists. The hospital has huge total capacity, but each patient's visit is fast and cheap.
  • Result: massive total parameters with only a fraction active — fast and cheap at inference
MoE isn't new — it dates back to 1991 (Jacobs et al.). But scaling it to transformers required solving routing instability and load balancing (making sure all experts get used, not just a few favourites). Google's Switch Transformer (2021) was the breakthrough paper.

⚡ Mixture of Experts (MoE)

  • Standard Transformer: every token passes through one large feed-forward network (FFN) — all parameters active
  • MoE replaces the FFN with N parallel "expert" sub-networks + a lightweight router
  • Router = a small classifier that picks the top-K experts for each token (typically K=2 of 8–64)
  • Result: huge total parameters, tiny active parameter count — knowledge scales, compute does not
Example: DeepSeek-V4 Pro — 1.6T total params, only 49B active per token (3%). Frontier capability at roughly the compute cost of a 49B dense model.
The router is trained jointly with the network — it learns to specialise experts on different types of content (syntax, factual recall, reasoning, etc.), though the specialisation is emergent, not explicit. Two training challenges: (1) collapse — early training tends to route all tokens to one expert; fixed by adding noise to router logits. (2) load imbalance — some experts become over-subscribed; fixed by capping tokens per expert and routing overflow to the next-best alternative. Why does total parameter count predict capability better than active count? Li (2026, arXiv:2604.24827) shows R²=0.79 for total params vs 0.51 for active — factual knowledge is distributed across all experts, not just the ones that fire per token.

Section 4

Training Methods

Tokens, reinforcement learning, and energy

Pre-training from Scratch: Token Counts

  • One token ≈ ¾ of a word
  • Pre-training = feeding the model trillions of tokens, one next-token prediction at a time
  • Modern open models use 10–20× more tokens than early GPT models
  • More tokens → more knowledge, better reasoning — up to a point
For context: the entire English Wikipedia is about 4 billion tokens. LLaMA 3 trained on the equivalent of ~3,750 Wikipedias. Qwen 2.5's 18 trillion tokens represent a significant investment in data collection, cleaning, and deduplication — often more expensive than the compute itself.

What's in the Training Data?

  • Web crawls (Common Crawl): biggest source — but noisy, needs heavy filtering
  • Books: high-quality, long-form reasoning
  • Code: GitHub repositories — dramatically improves structured reasoning
  • Scientific papers: arXiv, PubMed
  • Math: textbooks, competition problems, formal proofs
The Phi series (Microsoft) showed that training on carefully curated "textbook quality" data could produce surprisingly capable small models. Code training is particularly important — it teaches models to think step-by-step, which transfers to non-code reasoning tasks.

🧠 Reinforcement Learning for Reasoning

  • Pre-training gives broad knowledge. RL teaches the model to think harder
  • Key idea: reward the model when its chain of thought leads to a correct answer
  • The model learns to self-verify, backtrack, and try multiple approaches
  • No human labels needed for the reasoning steps — just a verifiable final answer
DeepSeek-R1 (Jan 2025): trained purely with RL on math and coding problems. The model spontaneously developed an "aha moment" — learning to pause, reflect, and reconsider wrong answers mid-generation.
  • OpenAI o1/o3: similar approach — "thinking tokens" before answering
  • Trade-off: much slower and more expensive at inference time
The "aha moment" in DeepSeek-R1 was genuinely surprising — it emerged from RL without being explicitly programmed. The model learned phrases like "Wait, let me reconsider..." as a useful strategy. This is an example of emergent behavior from training incentives alone. OpenAI's o3 uses a similar approach and achieved unprecedented scores on ARC-AGI.

Chain of Thought: Reasoning Step-by-Step

Without chain of thought:

Q: "If a train leaves at 9am at 60 km/h and another at 10am at 80 km/h, when do they meet?"

A: "11:30am"  ❌

With chain of thought:

A: "Train 2 starts 1 hour later. In 1 hour, Train 1 covers 60 km. Train 2 closes the gap at 80−60=20 km/h. Time to close: 60/20 = 3 hours. Train 2 departs 10am + 3h = 1pm ✓"
  • Wei et al. (2022, Google): simply adding "Let's think step by step" dramatically improves accuracy
  • RL-trained reasoning models generate much longer, richer thought traces
  • Test-time compute: spending more tokens thinking → better answers
Chain of thought prompting was one of the most surprising findings in recent NLP: you don't need to change the model at all — just asking it to think aloud massively improves performance on multi-step reasoning tasks. RL-trained models internalize this and do it automatically.

⚡ Energy: The Cost of Intelligence

  • Training GPT-3: ~1,300 MWh — powering ~120 US homes for a year
  • Training a frontier model today: estimated 50–100+ GWh
  • Per-query energy (early estimate): ChatGPT ~10× a Google search — but 2025 figures suggest the gap has narrowed as models became more efficient
  • At ~1B+ daily queries, even small per-query costs add up to enormous totals
  • IEA projects AI could double data-centre electricity use by 2026
Microsoft, Google, and Amazon have all made major investments in nuclear energy (SMRs) specifically to power AI data centres.
The efficiency race: DeepSeek V3 achieved frontier performance at a fraction of the energy cost — proving that clever algorithms can reduce the footprint significantly.
The energy estimates for frontier training are rough — labs don't publicly disclose. The 1,287 MWh for GPT-3 is from Patterson et al. (2021) at Google. The 50–100+ GWh for GPT-4 is speculative extrapolation. The "10× more than Google search" figure (de Vries 2023) is now contested: more recent 2025 analyses (Epoch AI, Hannah Ritchie) put a GPT-4o query at ~0.3 Wh, roughly on par with a modern Google search — efficiency gains have been substantial. Microsoft signed a deal to restart Three Mile Island nuclear plant for AI power.

Section 6

The Future of LLMs

What comes next — and what remains unknown

Are Scaling Laws Hitting a Wall?

  • Pre-training data is running out — the public internet has been largely consumed
  • Post-2024: diminishing returns reported for naive pre-training scale
  • Responses from the field:
  • → Synthetic data: generate training data with existing models
  • → Test-time compute: spend more tokens "thinking" per query (o1/o3/R1)
  • → Better architectures: MoE, attention variants, state-space models
  • → Better data curation: quality over quantity
The next scaling era may be in inference compute rather than training compute — models that "think longer" on hard problems.
Some researchers (e.g. Ilya Sutskever) believe we've exhausted the "low-hanging fruit" of internet pre-training. The shift to synthetic data and test-time scaling is a meaningful change in direction. Mamba and other state-space models are challengers to the transformer architecture, though they haven't yet matched it at scale.

Reasoning & Planning

  • Current LLMs are good at pattern recognition — less good at multi-step planning
  • RL-trained reasoning models (o3, R1) are a major step forward — but still brittle
  • Open problems:
  • → Reliable multi-step tool use: search, code execution, API calls
  • → Long-horizon planning: decompose complex goals over many steps
  • → Self-correction: detect and fix errors during generation
  • → World models: understanding causality and physical dynamics
The gap between "very good at language tasks" and "can reliably solve novel real-world problems" is large — and closing faster than most expected.
ARC-AGI is a benchmark designed specifically to test novel reasoning that can't be solved by pattern matching. o3 scored 87.5% in high-compute mode — up from ~5% for GPT-4. But it used enormous compute per problem. The challenge is making this efficient and reliable.

🤖 Agents: LLMs That Act

  • An agent is an LLM connected to tools: web search, code execution, file systems, APIs
  • The model decides which tool to call, interprets the result, and plans the next step
  • Applications: software engineering (Devin, Claude Code), research, data analysis
  • Multi-agent systems: multiple models collaborating, checking each other's work
SWE-Bench: real GitHub software bugs. GPT-4 (2023): ~2% solved. Claude 3.5 Sonnet (2024): ~49%. DeepSeek-V4 Pro (2026): 80.6% — a 40× improvement in 3 years.
Risk: agents that take real-world actions can cause real-world harm. Reliability, oversight, and permission systems are active research areas.
Claude Code (what is being used to help me prepare these slides!) is an example of an AI coding agent. SWE-bench measures the ability to fix real GitHub issues in popular open-source repositories — far harder than toy coding problems. The jump from 2% to 50%+ in 18 months is remarkable.

Open Challenges

  • Hallucination — models confidently state false information
  • Reasoning reliability — small prompt changes cause large performance swings
  • Context limits — even 1M-token windows struggle with very long documents
  • Evaluation — benchmarks saturate; measuring real-world capability is hard
  • Interpretability — we don't understand how models reach conclusions
  • Alignment — reliably making models do what we want
  • Compute efficiency — sustainable energy use at scale
  • Data scarcity — what to train on next
Every one of these is an active research area with PhD-level careers attached. The field is not "solved" — it has never been more open.
Interpretability (mechanistic interpretability) is a field trying to reverse-engineer what computations are happening inside neural networks. Anthropic, DeepMind, and academic labs have made progress — identifying "features" and "circuits" — but we're still far from a full mechanistic account.
